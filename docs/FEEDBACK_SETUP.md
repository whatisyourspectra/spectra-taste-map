# 문의·피드백 수집

웹 오른쪽 아래의 **사용 안내 · 문의**에서 사용법을 확인하거나 **문의 남기기**를 선택할 수 있습니다. 모바일 지도에서는 더 보기 메뉴의 같은 항목으로 진입합니다. 로그인 없이 제출할 수 있고, 로그인한 경우 Supabase가 확인한 계정 ID가 연결됩니다.

## 데이터베이스 적용

1. 기존 스펙트라 Supabase 프로젝트의 SQL Editor에서 [user_feedback.sql](./user_feedback.sql) 전체를 실행합니다.
2. 기존 `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY` 또는 `VITE_SUPABASE_ANON_KEY`를 그대로 사용합니다. 새 비밀키나 메일 설정은 필요하지 않습니다.
3. 앱에서 문의를 제출하고 Table Editor → `user_feedback`에 행이 생성되는지 확인합니다.

현재 작업환경에는 데이터베이스 관리자 접속 정보가 없어 SQL을 원격 적용하지 않았습니다. SQL을 적용하기 전에는 제출에 실패하며 성공 메시지를 표시하지 않습니다.

2026-10-20 배포 점검에서는 운영 RPC에 필수 인자들을 포함하되 유효하지 않은 UUID와 동의 거부 값을 담은 GET 요청을 보내 PostgreSQL의 UUID 형식 오류(`22P02`)를 확인했습니다. 제출 함수의 시그니처가 운영 환경에 등록되어 있음을 확인한 결과이며, 실제 문의를 전송하거나 문의 데이터를 생성하지 않았습니다. 실제 접수와 운영자의 조회까지 검증한 결과는 아닙니다.

## 운영자가 확인하기

Supabase Table Editor에서 `created_at` 내림차순으로 정렬하고 `status = new`로 필터링합니다. 처리 중에는 `reviewing`, 완료 후 `resolved`로 바꿀 수 있습니다. 이메일을 입력한 경우에만 운영자가 해당 주소로 별도 답변할 수 있으며, 자동 이메일 발송 기능은 포함하지 않습니다.

수집 항목: 문의 유형, 제목, 내용, 선택 이메일, 화면 경로(쿼리·해시 제외), 모바일/데스크톱, 접수·동의 시각, 로그인 계정 ID(있는 경우), 브라우저 세션 식별자. 지도·곡 목록·액세스 토큰·전체 브라우저 정보는 전송하지 않습니다.

## 접근과 재시도

- 테이블은 RLS를 활성화하고 일반 사용자에게 직접 읽기·쓰기 권한을 부여하지 않습니다. 제한된 제출 함수만 실행할 수 있습니다. 상태·계정 ID·시간은 데이터베이스에서 설정합니다.
- 기본 제한은 브라우저 세션 또는 로그인 계정 기준 15분에 5건입니다. 익명 세션을 새로 만들면 우회할 수 있으므로 인터넷 전체에 대한 강력한 봇 방어는 아닙니다.
- 제출 실패 시 입력값을 유지합니다. 같은 내용의 재시도에는 같은 요청 ID를 사용해 중복 저장을 막습니다. 제목이나 내용을 수정하면 새 요청으로 처리합니다.
- 로컬 Mock 계정은 실제 Supabase 로그인 계정으로 저장되지 않습니다.

검증: `node --test tests/feedback.test.mjs`, `npm run build`. 실제 원격 저장과 권한 검증은 SQL 적용 후 해당 Supabase 프로젝트에서 확인해야 합니다.

추가 검증 스크립트:

- `tests/browser/feedback.mjs`: `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `BASE_URL` 환경 변수로 로컬 브라우저 테스트를 실행할 수 있습니다. 저장 RPC만 모의 응답으로 대체해 웹·모바일의 실패/재시도/성공 흐름을 확인합니다.
- `tests/browser/feedbackDatabase.mjs`: `PGLITE_MODULE`에 설치된 `@electric-sql/pglite`의 모듈 경로를 지정하면 로컬 메모리 PostgreSQL에서 실제 SQL을 실행합니다. 반복 적용, 익명/로그인 제출, 읽기와 직접 쓰기 차단, 입력 제한, 빈도 제한, 중복 방지를 확인합니다. 원격 데이터베이스에 접근하지 않습니다.
