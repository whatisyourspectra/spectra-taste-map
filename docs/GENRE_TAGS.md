# 장르 태그 정제와 분류

정제 버전: `MUSIC_TAG_VERSION = 2`. 규칙과 예외는 `src/taste/musicTags.js`에서 관리합니다. 태그 기반 휴리스틱이며 음원을 직접 분석하거나 분류 정확도를 측정한 모델이 아닙니다.

## 태그 종류

| 입력 예 | 처리 |
| --- | --- |
| hip-hop / hiphop / Hip Hop | `hip hop`으로 통합 |
| RNB / R & B | `r&b`로 통합 |
| deep house / tech house | 각각의 세부 장르 유지 |
| chill / happy / dreamy | `moodTags`에 보관, 장르 집계 제외 |
| 90s / 1990s | `eraTags`의 `1990s`로 통합 |
| instrumental / acoustic | `styleTags`에 보관 |
| favorites / seen live / female vocalists | `contextTags`에 보관 |
| 아직 확인하지 않은 태그 | `otherTags`에 보관, 장르로 추측하지 않음 |

원본 문자열은 `rawTags`로 남깁니다. `chillout`처럼 장르와 분위기 양쪽의 용법을 지원하는 태그는 두 목록에 포함될 수 있습니다. 아티스트·곡명과 같은 미확인 태그는 분류에서 제외하지만, 곡명이 Jazz인 경우처럼 사전에 명시된 실제 장르와 일치하면 유지합니다. Beach House, Daft Punk처럼 장르 단어로 끝나는 아티스트명은 장르로 취급하지 않습니다.

새 가져오기·추천 응답은 정제한 `genres`, 원본과 종류별 태그, `tagVersion`, `genreSource`를 담습니다. 기본 필드에서는 곡 수준 Last.fm 장르를 우선하고, 쓸 수 있는 장르가 없을 때 아티스트 태그로 보완합니다. 이때 원래 곡에 붙은 무드·시대 태그도 보관합니다. Spotify 아티스트 장르는 별도의 필드에서 정제하며 기본 필드에 임의로 합치지 않습니다.

## 지도 분류

데스크톱·모바일·취향 집계는 같은 정제 함수를 사용합니다. 기존에 저장한 지도는 읽을 때 태그를 해석하므로 파일을 다시 가져올 필요가 없고, 기존 원본 곡·태그·저장 시각은 수정하지 않습니다. 기존 무드/에너지 수치를 자동으로 재계산하지 않습니다.

### 전체 곡을 포함하는 최대 15개 분류

`genreClustering.js`의 `partitionGenreTracks`를 데스크톱 Worker와 모바일 모델이 함께 사용합니다. 분류 버전은 `GENRE_PARTITION_VERSION = 2`이며 빈 라이브러리를 제외하면 다음을 보장합니다.

- 분류 수는 최대 15개이고 빈 분류를 만들지 않습니다. `전체` 버튼은 이 개수에 포함하지 않습니다.
- 가져온 고유 곡마다 분류 ID를 정확히 하나 배정합니다. 여러 장르가 있어도 필터 간 곡의 중복은 없습니다.
- 각 분류의 곡 수 합계는 현재 라이브러리의 고유 곡 수와 같습니다. 분석 중·특징값 없음·장르 없음·단 한 곡짜리 장르도 제외하지 않습니다.
- 메타데이터가 부족한 곡은 `장르 정보 없음 / Genre Unknown`에 포함하며, 이 태그도 15개 한도에 포함합니다. 음원 특징을 추정해 특정 장르로 강제 배정하지 않습니다.
- 원본 곡의 여러 태그는 유지합니다. 분류는 탐색을 위한 대표 영역 선택이며 곡의 유일한 음악 장르라는 뜻은 아닙니다.

먼저 정제된 태그들을 Pop, Hip Hop, R&B/Soul, Rock, Indie/Alternative, Metal/Punk, Electronic, Ambient/Downtempo, Jazz/Blues, Folk/Country, Classical/Soundtrack, Reggae/Dub, World/Regional 및 기타 장르의 14개 큰 계열로 해석합니다. 태그별 투표량은 1에 명시된 부모 단계 수의 0.1배를 더한 값입니다. 곡마다 합계가 가장 높은 계열 하나를 고르고, 그 안에서 부모 관계가 더 구체적인 장르, 라이브러리 내 빈도, 사전순으로 대표 태그를 선택합니다. 아티스트 이름이나 국적에 대한 예외 규칙은 없습니다.

계열 → 부모 장르 → 세부 장르의 트리를 만든 뒤, 자식이 하나뿐인 단계는 압축합니다. 따라서 모두 House인 라이브러리는 Electronic 대신 House로 표시할 수 있습니다. 15개 예산 안에서 정보량 이득이 큰 영역부터 세분화합니다. 필요한 자식 수가 남은 예산보다 많으면 큰 자식들을 먼저 표시하고 나머지를 `House · Other`처럼 **공통 상위 장르의 나머지 분류**로 남깁니다. 상위 N개만 잘라 나머지 곡을 숨기거나 무관한 장르를 가까운 군집으로 강제 합치지 않습니다.

데스크톱 상단 태그·검사 패널·개요와 모바일 장르 필터는 만들어진 전체 분류를 표시합니다. 각 태그의 곡 수를 보여주고 모바일 필터도 곡의 단일 배정 ID를 사용합니다. 기존처럼 한 곡의 여러 태그를 각각 집계해 합계가 전체보다 커지는 방식은 사용하지 않습니다.

TF-IDF 벡터는 계속 대표곡 거리 계산에 사용합니다. 직접 태그 128개, 추가 부모 신호 16개 한도와 부모 가중치 0.45/0.225가 적용되지만, **분류 자체는 한도 전의 전체 정제 태그로 결정**하므로 어휘 한도 밖의 곡도 누락되지 않습니다. 기존 오디오 특징 DBSCAN은 오디오 기준 요청에만 사용합니다.

클러스터 캐시는 v6으로 교체하고 분류 이름과 종류도 저장합니다. 캐시의 배정 수·그룹 수·ID 범위를 검증한 뒤 읽으며 오래된 결과는 재계산합니다. 원본 파일을 다시 가져올 필요는 없습니다. 분류 근거에는 원본의 다른 장르 태그도 전체 곡 대비 개수로 계속 표시합니다.

장르 기반 무드 추정은 `indie rock` 같은 구체적인 규칙을 먼저 선택합니다. `happy`가 `unhappy`에 부분 일치하는 방식은 사용하지 않습니다. 수치는 계속 태그 기반 추정값입니다.

## 검증 범위와 다음 단계

`tests/musicTags.test.mjs`는 별칭 통합, 원본 보존, 장르 외 태그 분리, 기존 지도 적용, 부모 신호, 실제 Worker 결과를 검증합니다. `tests/genreClustering.test.mjs`는 Frank Ocean 예시와 동아시아 인디의 분리, 희귀 장르와 어휘 한도 밖 태그, 정보 부족·한 곡짜리 입력, 5,000곡의 최대 15개 완전 분할·합계·입력 순서 안정성을 검증합니다. 예시 태그는 2026-11-03 Last.fm `artist.getTopTags` 조회값이며, 사용자 개인 지도의 특정 곡을 확인했다는 뜻은 아닙니다. 브라우저 검사는 85곡의 데스크톱/모바일 태그 합계, 분석 대기 곡의 선택, 전체 태그 표시와 캐시 복원을 확인합니다.

계열 사전과 대표 장르 선택은 제품 규칙이며 정답 데이터로 학습한 분류기는 아닙니다. 15개 한도 때문에 일부 세부 장르가 공통 상위 영역에 통합될 수 있습니다. 모든 곡의 포함과 음악학적 분류 정확도는 별개이며, 후자는 실제 사용자 표본에서 추가 평가해야 합니다.

다음 단계는 자발적으로 제공한 실제 곡 표본에서 과도하게 제외된 장르와 서로 혼동되는 영역을 검토하는 것입니다. 그 결과에 따라 별칭·분류 사전을 확장하고, 곡/아티스트 출처별 가중치와 사용자 수동 수정을 설계할 수 있습니다.
