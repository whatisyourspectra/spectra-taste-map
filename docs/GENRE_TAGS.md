# 장르 태그 정제와 분류

정제 버전: `MUSIC_TAG_VERSION = 2`. 규칙과 예외는 `src/taste/musicTags.js`에서 관리합니다. 태그 기반 휴리스틱이며 음원을 직접 분석하거나 분류 정확도를 측정한 모델이 아닙니다.

## 태그 종류

| 입력 예 | 처리 |
| --- | --- |
| hip-hop / hiphop / Hip Hop | `hip hop`으로 통합 |
| RNB / R & B | `r&b`로 통합 |
| deep house / tech house | 각각의 세부 장르 유지 |
| chill / happy / dreamy | `moodTags`에 보관, 장르 집계 제외 |
| 90s / 1990s | `eraTags`의 `1990s`로 통합 |
| instrumental / acoustic | `styleTags`에 보관 |
| favorites / seen live / female vocalists | `contextTags`에 보관 |
| 아직 확인하지 않은 태그 | `otherTags`에 보관, 장르로 추측하지 않음 |

원본 문자열은 `rawTags`로 남깁니다. `chillout`처럼 장르와 분위기 양쪽의 용법을 지원하는 태그는 두 목록에 포함될 수 있습니다. 아티스트·곡명과 같은 미확인 태그는 분류에서 제외하지만, 곡명이 Jazz인 경우처럼 사전에 명시된 실제 장르와 일치하면 유지합니다. Beach House, Daft Punk처럼 장르 단어로 끝나는 아티스트명은 장르로 취급하지 않습니다.

새 가져오기·추천 응답은 정제한 `genres`, 원본과 종류별 태그, `tagVersion`, `genreSource`를 담습니다. 기본 필드에서는 곡 수준 Last.fm 장르를 우선하고, 쓸 수 있는 장르가 없을 때 아티스트 태그로 보완합니다. 이때 원래 곡에 붙은 무드·시대 태그도 보관합니다. Spotify 아티스트 장르는 별도의 필드에서 정제하며 기본 필드에 임의로 합치지 않습니다.

## 지도 분류

데스크톱·모바일·취향 집계는 같은 정제 함수를 사용합니다. 기존에 저장한 지도는 읽을 때 태그를 해석하므로 파일을 다시 가져올 필요가 없고, 기존 원본 곡·태그·저장 시각은 수정하지 않습니다. 기존 무드/에너지 수치를 자동으로 재계산하지 않습니다.

데스크톱 장르 클러스터링은 정제한 장르의 TF-IDF 벡터를 사용합니다. `deep house → house → electronic`처럼 명시한 관계를 약한 추가 신호로 사용하되 세부 장르 이름은 유지합니다. 장르 자체의 가중치는 1, 부모 신호는 첫 단계 0.45와 두 번째 단계 0.225입니다. 여러 태그를 가진 곡은 벡터의 길이를 정규화해 태그 수 때문에 영향력이 커지지 않게 합니다. 기본 어휘 한도는 직접 태그 128개와 추가 부모 신호 16개입니다. 한도 밖 태그의 부모 신호만 남은 곡은 그 부모만으로 군집에 넣지 않습니다.

새 장르 벡터와 기존 클러스터 캐시가 섞이지 않도록 캐시 버전을 올렸습니다. 캐시를 다시 읽을 때도 같은 벡터를 복원해 영역 대표곡의 거리 계산이 일치하도록 합니다.

장르 군집은 `genreClustering.js`의 고정 대표 프로필 기준으로 구성합니다. 동일 장르 조합의 곡을 모아 빈도가 높은 프로필부터 처리하고, 동률은 태그 수와 사전순으로 정렬해 입력 순서의 영향을 없앱니다. 같은 군집에 들어가려면 최초 대표 프로필과 코사인 유사도 0.68 이상이고, 군집 전체에 공통인 직접 장르가 하나 이상 있어야 합니다. 대표 벡터를 이동시키거나 이웃의 이웃만으로 합치지 않아 연쇄 병합을 막습니다. 특정 아티스트에 대한 예외 규칙은 없습니다.

최소 두 곡의 근거가 있는 그룹만 군집으로 만들고, 단독 프로필·장르 없음·부모 신호만 있는 곡은 `Mixed / Other`로 표시합니다. 이는 하나의 음악 장르를 의미하는 군집이 아니라 아직 묶을 근거가 부족한 곡들의 모음입니다. 전체 라이브러리에 장르가 전혀 없는 경우에는 기존 오디오 특징 DBSCAN으로 대체하며, 그 특징은 실제 음원 측정값이 아닌 태그 기반 추정값일 수 있습니다.

영역 이름은 군집 내 곡의 60% 이상이 가진 태그만 최대 두 개 사용합니다. `Taiwanese Indie`, `Japanese Indie` 같은 명시적 지역 수식 태그는 전체 곡에 해당할 때만 이름에 사용합니다. 실제 지역 태그를 삭제하거나 서양 아티스트라는 이유로 장르를 바꾸지 않습니다. 분류 근거에는 소수 태그도 전체 곡 대비 개수로 계속 표시합니다. 기존 군집 캐시는 v5로 교체해 새로 연 지도에 이전 결과가 남지 않게 합니다.

장르 기반 무드 추정은 `indie rock` 같은 구체적인 규칙을 먼저 선택합니다. `happy`가 `unhappy`에 부분 일치하는 방식은 사용하지 않습니다. 수치는 계속 태그 기반 추정값입니다.

## 검증 범위와 다음 단계

`tests/musicTags.test.mjs`는 별칭 통합, 원본 보존, 장르 외 태그 분리, 기존 지도 적용, 부모 신호, 실제 Worker 결과를 검증합니다. `tests/genreClustering.test.mjs`는 Frank Ocean 아티스트 태그 예시와 동아시아 인디의 분리, 연쇄 병합 방지, 소수 지역 태그의 대표 이름 제외, 32개를 넘는 어휘, 정보 부족과 두 곡짜리 입력을 검증합니다. 예시 태그는 2026-11-03 Last.fm `artist.getTopTags` 조회값이며, 사용자 개인 지도에 저장된 특정 곡의 태그를 확인했다는 뜻은 아닙니다.

유사도 0.68, 이름 기준 60%, 최소 두 곡과 어휘 한도는 보수적 제품 규칙이며 정답 데이터로 최적화한 값은 아닙니다. 기존보다 영역이 세분되거나 `Mixed / Other`가 늘 수 있습니다. 특정 장르의 정답이 붙은 실제 사용자 곡 집합에 대한 정확도나 사용자 만족도 개선은 아직 측정하지 않았습니다.

다음 단계는 자발적으로 제공한 실제 곡 표본에서 과도하게 제외된 장르와 서로 혼동되는 영역을 검토하는 것입니다. 그 결과에 따라 별칭·분류 사전을 확장하고, 곡/아티스트 출처별 가중치와 사용자 수동 수정을 설계할 수 있습니다.
