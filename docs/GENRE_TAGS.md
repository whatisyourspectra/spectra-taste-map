# 장르 태그 정제와 분류

정제 버전: `MUSIC_TAG_VERSION = 1`. 규칙과 예외는 `src/taste/musicTags.js`에서 관리합니다. 태그 기반 휴리스틱이며 음원을 직접 분석하거나 분류 정확도를 측정한 모델이 아닙니다.

## 태그 종류

| 입력 예 | 처리 |
| --- | --- |
| hip-hop / hiphop / Hip Hop | `hip hop`으로 통합 |
| RNB / R & B | `r&b`로 통합 |
| deep house / tech house | 각각의 세부 장르 유지 |
| chill / happy / dreamy | `moodTags`에 보관, 장르 집계 제외 |
| 90s / 1990s | `eraTags`의 `1990s`로 통합 |
| instrumental / acoustic | `styleTags`에 보관 |
| favorites / seen live / female vocalists | `contextTags`에 보관 |
| 아직 확인하지 않은 태그 | `otherTags`에 보관, 장르로 추측하지 않음 |

원본 문자열은 `rawTags`로 남깁니다. `chillout`처럼 장르와 분위기 양쪽의 용법을 지원하는 태그는 두 목록에 포함될 수 있습니다. 아티스트·곡명과 같은 미확인 태그는 분류에서 제외하지만, 곡명이 Jazz인 경우처럼 실제 장르와 일치하면 유지합니다.

새 가져오기·추천 응답은 정제한 `genres`, 원본과 종류별 태그, `tagVersion`, `genreSource`를 담습니다. 기본 필드에서는 곡 수준 Last.fm 장르를 우선하고, 쓸 수 있는 장르가 없을 때 아티스트 태그로 보완합니다. 이때 원래 곡에 붙은 무드·시대 태그도 보관합니다. Spotify 아티스트 장르는 별도의 필드에서 정제하며 기본 필드에 임의로 합치지 않습니다.

## 지도 분류

데스크톱·모바일·취향 집계는 같은 정제 함수를 사용합니다. 기존에 저장한 지도는 읽을 때 태그를 해석하므로 파일을 다시 가져올 필요가 없고, 기존 원본 곡·태그·저장 시각은 수정하지 않습니다. 기존 무드/에너지 수치를 자동으로 재계산하지 않습니다.

데스크톱 장르 클러스터링은 정제한 장르의 TF-IDF 벡터를 사용합니다. `deep house → house → electronic`처럼 명시한 관계를 약한 추가 신호로 사용하되 세부 장르 이름은 유지합니다. 장르 자체의 가중치는 1, 부모 신호는 첫 단계 0.45와 두 번째 단계 0.225입니다. 여러 태그를 가진 곡은 벡터의 길이를 정규화해 태그 수 때문에 영향력이 커지지 않게 합니다. 기본 어휘 한도는 직접 태그 32개와 추가 부모 신호 8개입니다.

새 장르 벡터와 기존 클러스터 캐시가 섞이지 않도록 캐시 버전을 올렸습니다. 캐시를 다시 읽을 때도 같은 벡터를 복원해 영역 대표곡의 거리 계산이 일치하도록 합니다.

어휘 차원이 늘었다는 이유만으로 최소 군집 크기가 계속 커지지 않도록 DBSCAN의 최소 이웃 수를 최대 18로 제한합니다. 실제 음악 데이터에서 적절한 군집 크기는 별도 평가 대상입니다.

장르 기반 무드 추정은 `indie rock` 같은 구체적인 규칙을 먼저 선택합니다. `happy`가 `unhappy`에 부분 일치하는 방식은 사용하지 않습니다. 수치는 계속 태그 기반 추정값입니다.

## 검증 범위와 다음 단계

`tests/musicTags.test.mjs`는 별칭 통합, 원본 보존, 장르 외 태그 분리, 기존 지도 적용, 부모 신호, 실제 Worker 결과를 검증합니다. 특정 장르의 정답이 붙은 실제 사용자 곡 집합에 대한 정확도나 사용자 만족도 개선은 아직 측정하지 않았습니다.

다음 단계는 자발적으로 제공한 실제 곡 표본에서 과도하게 제외된 장르와 서로 혼동되는 영역을 검토하는 것입니다. 그 결과에 따라 별칭·분류 사전을 확장하고, 곡/아티스트 출처별 가중치와 사용자 수동 수정을 설계할 수 있습니다.
