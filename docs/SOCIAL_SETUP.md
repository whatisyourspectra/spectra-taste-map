# Social v1

`/social`에서 공개된 취향을 둘러보고 `/social/:userId`에서 대표곡과 코멘트를 봅니다. 로그인하지 않아도 공개 페이지를 읽을 수 있고, 공개와 코멘트 작성에는 실제 Supabase 로그인이 필요합니다. 랜딩과 데스크톱 지도에 Social 진입점을, 모바일에 네 번째 Social 탭을 추가했습니다.

## 운영 DB 적용

기존 Supabase 프로젝트의 SQL Editor에서 [social_taste.sql](./social_taste.sql) 전체를 실행합니다. 반복 실행할 수 있으며 기존 `user_taste_maps`와 공유 링크 테이블은 변경하지 않습니다. 기존 `VITE_SUPABASE_URL`, publishable/anon 키를 그대로 사용합니다. 추가 비밀키는 필요하지 않습니다.

현재 작업환경에는 DB 관리자 접속 정보가 없어 운영 DB에 SQL을 적용하지 않았습니다. 코드와 SQL은 로컬에서 검증했습니다. 운영 연결 검증이 완료됐다는 뜻은 아닙니다. 테이블/RPC가 준비되지 않으면 화면은 연결 오류와 재시도를 표시하며 공개·코멘트 성공으로 처리하지 않습니다.

적용 후 두 실제 계정으로 다음을 확인합니다.

1. 계정 A로 개인 음악을 가져오고 Social의 공개 미리보기를 확인한 뒤 공개합니다.
2. 시크릿 브라우저에서 공개 URL을 열어 읽기만 가능한지 확인합니다.
3. 계정 B로 코멘트를 남기고 B와 A가 각각 자신의 권한으로 삭제할 수 있는지 확인합니다.
4. A가 공개를 해제한 뒤 새 요청에서 프로필과 코멘트가 숨겨지고 추가 작성이 차단되는지 확인합니다.

## 공개되는 데이터와 갱신

자동 공개는 하지 않습니다. 사용자가 버튼을 누르면 닉네임, 소개, 곡 수, 장르 분포와 선택한 대표곡 최대 24곡의 **스냅샷**을 저장합니다. 대표곡 공개는 해제할 수 있습니다. 대표곡은 상위 장르에서 선별하고 아티스트당 세 곡으로 제한합니다. 데모는 공개하지 않습니다. 원본 개인 지도 ID·개인 이력·이메일·자격증명은 직렬화하지 않습니다.

개인 지도가 바뀌어도 공개 데이터는 자동 변경하지 않습니다. 사용자가 `공개 취향 업데이트`를 눌러 갱신합니다. 공개 해제는 스냅샷과 코멘트를 보관하면서 이후 공개 조회를 막습니다. 이미 타인의 브라우저에 내려받은 내용까지 회수하는 기능은 아닙니다.

## 저장과 권한

- `social_taste_profiles`: 계정당 하나. RLS로 공개된 행과 본인 행만 읽고, 본인만 삽입·수정합니다. 공개 시각과 갱신 시각은 DB에서 관리합니다.
- `social_taste_comments`: 공개 프로필에서만 일반 열람할 수 있습니다. 비공개 전환 시 프로필 주인만 기존 코멘트를 볼 수 있고, 작성자·프로필 주인만 삭제할 수 있습니다.
- 코멘트는 제한된 `add_social_taste_comment` RPC로만 작성합니다. 인증 계정 ID를 DB가 결정하고 다른 작성자 ID를 전달할 수 없습니다. 작성 닉네임은 사용자 선택이며 고유한 계정명이나 인증 배지가 아닙니다.
- 본문 1~1,000자, 닉네임 1~40자, 계정당 최근 10분간 보관된 코멘트 최대 20건으로 제한합니다. 삭제나 새 계정으로 우회할 수 있어 강한 봇 방어를 의미하지 않습니다.
- 동일 요청 ID의 재시도는 기존 행을 반환합니다. 같은 ID에 다른 내용이나 작성자·대상을 전달하면 거부합니다. 비공개 전환과 작성은 DB 행 잠금으로 직렬화합니다.
- 피드는 12개, 코멘트는 30개 단위로 추가 로딩합니다. 최신 코멘트는 새로고침으로 불러오며 실시간 구독은 포함하지 않습니다.

## 다음 취향 비교 단계

스냅샷 `version: 1`과 태그 정제 버전 `tagVersion`에 정규화된 `genreProfile: [{ genre, strength }]`를 저장합니다. 태그가 여러 개인 곡은 전체 기여량을 나눠 장르 수가 많은 곡이 과도하게 영향을 주지 않게 합니다. 그래픽의 각 점은 곡이 아닌 장르를 나타냅니다. 상위 16개 장르를 시각화하고 최대 512개 분포를 저장합니다.

유사도 점수는 아직 계산하거나 표시하지 않습니다. 다음 단계에서는 분류 버전·출처 정합성, 정보량이 부족한 프로필 처리와 실제 사용자 표본 검증을 포함해 비교 기준을 정해야 합니다. 이번 장르 분포를 곧바로 취향의 정답이나 음원 유사도로 해석하지 않습니다.

## 검증

- `node --test tests/social.test.mjs`: 공개 스냅샷 범위, 데모 차단, 안전한 읽기, 저장 확인, 요청 ID, 로그인 복귀 경로.
- `PGLITE_MODULE=... node tests/browser/socialDatabase.mjs`: 실제 SQL 재적용, RLS, 인증 작성자, 공개 해제, 권한별 삭제, 입력 검증·빈도 제한·중복 방지. 연결된 운영 DB에 접근하지 않습니다.
- `PLAYWRIGHT_MODULE=... CHROMIUM_EXECUTABLE=... node tests/browser/social.mjs`: 테스트용 저장 응답으로 두 계정과 비로그인, 데스크톱·모바일, 실패·재시도·삭제·비공개 전환을 검증합니다.
- `npm test`, `npm run build`.
